# Purpose

This document defines how events are created, planned, scheduled, coordinated, and managed throughout their lifecycle.

The planning system supports both simple weekly kennel runs and complex international events with multiple venues, activities, committees, and thousands of attendees.

---

# Philosophy

Successful events begin with good planning.

Planning should be collaborative, transparent, and adaptable as circumstances change.

Every participant should understand where they need to be, when, and why.

---

# Guiding Principles

- One source of truth.
- Flexible scheduling.
- Collaborative planning.
- Real-time updates.
- Historical traceability.

---

# Event Structure

An event consists of one or more activities.

Example:

Interhash 2038

- Welcome Reception
- Registration Desk
- City Tour
- Day 1 Trail
- Beer Check
- Charity Auction
- AGM
- Red Dress Run
- Closing Ceremony

Each activity has its own schedule, venue, coordinators, and participants.

---

# FR-EVENT-001 — Event Creation

Organizers can create events by specifying:

- Name
- Event type
- Host kennel
- Description
- Theme
- Start and end dates
- Registration window
- Capacity
- Visibility
- Public website
- Branding assets

Events receive a permanent identifier.

---

# FR-EVENT-002 — Program Builder

Organizers build the official event programme using a drag-and-drop interface.

Activities may be:

- Sequential
- Parallel
- Optional
- Repeating

Dependencies between activities can be defined.

---

# FR-EVENT-003 — Multi-Day Scheduling

Support scheduling across multiple days.

Each day may include:

- Morning activities
- Afternoon activities
- Evening activities
- Overnight activities

Time zone handling is built into the scheduling engine.

---

# FR-EVENT-004 — Venue Assignment

Activities may be assigned to:

- Venues
- Parks
- Hotels
- Trailheads
- Meeting points
- Bus pickup locations

Venue capacity is validated automatically.

---

# FR-EVENT-005 — Resource Allocation

Resources may include:

- Volunteers
- Buses
- Equipment
- Medical teams
- Sound systems
- Registration desks
- Merchandise booths

Resource conflicts are detected before publication.

---

# FR-EVENT-006 — Committee Management

Organizers may create committees such as:

- Registration
- Trails
- Logistics
- Medical
- Entertainment
- Sponsorship
- Merchandise
- Hospitality

Each committee has defined members, responsibilities, and deadlines.

---

# FR-EVENT-007 — Task Management

Tasks support:

- Assignees
- Priorities
- Due dates
- Checklists
- Attachments
- Status tracking
- Comments

Tasks may belong to committees or specific activities.

---

# FR-EVENT-008 — Programme Publishing

Published programmes are available through:

- Mobile app
- Web portal
- Printable PDF
- Digital signage
- Public event page

Changes propagate automatically to all supported channels.

---

# FR-EVENT-009 — Schedule Changes

When schedules change:

- Participants receive notifications.
- Timelines update automatically.
- Conflicts are recalculated.
- Audit logs record all revisions.

Historical schedules remain archived.

---

# FR-EVENT-010 — Operational Dashboard

Organizers have access to a live operational dashboard displaying:

- Registration status
- Check-in counts
- Activity readiness
- Volunteer assignments
- Capacity alerts
- Weather alerts
- Incident reports
- Outstanding tasks

The dashboard updates in near real time.

---

# Business Principles

Planning should reduce uncertainty.

Schedules should remain adaptable.

Every change should be transparent.

---

# Completion Criteria

Complete when:

- Event creation is defined.
- Scheduling workflows exist.
- Resource management is supported.
- Committee management is documented.
- Live operational oversight is available.
