# Purpose

This document defines how Run Capsules are automatically assembled, enriched, finalized, and preserved throughout the lifecycle of a Hash Run.

Unlike traditional event archives, a Run Capsule is not created after the event—it grows continuously as the event unfolds.

---

# Philosophy

The best archive is the one that builds itself.

Participants should simply enjoy the run.

HCP quietly captures the story in the background.

By the time the Trail Report is published, most of the Run Capsule already exists.

---

# Guiding Principles

- Automatic wherever possible.
- Human approval where authenticity matters.
- Preserve every important moment.
- Never lose historical context.
- Every contribution has a place.

---

---

# Capsule States

Every Run Capsule transitions through the following states:

- Planned
- Preparing
- Live
- Draft
- Pending Publication
- Published
- Archived
- Legacy

Each state determines what information is visible and editable.

---

# FR-CAPSULE-001 — Automatic Capsule Creation

## Priority

Critical

A Run Capsule shall be created automatically when a Run Session is created.

Initial content includes:

- Run identity
- Kennel
- Scheduled date
- Assigned Hare(s)
- Planned trail metadata

The Capsule begins as a living draft.

---

# FR-CAPSULE-002 — Continuous Assembly

As the Run progresses, HCP automatically adds:

- Trail updates
- Waypoints
- Beer Checks
- Participant check-ins
- Photos
- Videos
- Audio
- Circle activities
- Story Cards
- Comments
- Reactions
- Attendance statistics

Each contribution is timestamped and linked to its source.

---

# FR-CAPSULE-003 — Story Integration

When the Official Trail Report is published:

- The report becomes the narrative centerpiece.
- Story Cards are linked.
- Timeline events are synchronized.
- AI summaries are updated.
- Historical references are generated.

---

# FR-CAPSULE-004 — Media Consolidation

All approved media related to the Run Session is automatically organized into:

- Galleries
- Albums
- Timeline collections
- Location collections
- Participant collections

Media retains attribution and metadata.

---

# FR-CAPSULE-005 — Timeline Construction

The platform automatically builds a chronological timeline including:

- Trail release
- Run start
- Beer Checks
- Scenic locations
- Circle opening
- Awards
- Trail Report publication

Additional events may be inserted manually by authorized users.

---

# FR-CAPSULE-006 — Historical Lock

Once the publication workflow is complete:

- The Run Capsule enters Published state.
- Core historical records become immutable.
- Subsequent corrections create revisions rather than overwriting history.

---

# FR-CAPSULE-007 — Incremental Enrichment

Even after publication, new supporting content may be attached without changing the historical record.

Examples include:

- Newly discovered photographs
- Scanned newsletters
- Interviews with long-time Hashers
- Anniversary reflections

These are stored as supplemental artifacts with clear timestamps.

---

# FR-CAPSULE-008 — Capsule Health

The system continuously validates Capsule completeness.

Indicators may include:

- Missing Trail Report
- Missing Circle information
- Uncaptioned media
- Incomplete participant roles
- Missing weather data

Health indicators assist officers without blocking publication.

---

# FR-CAPSULE-009 — Capsule Timeline

Readers may navigate the Run Capsule using an interactive timeline.

Timeline entries link directly to:

- Story Cards
- Media
- Map locations
- Trail Replay
- Trail Report sections

---

# FR-CAPSULE-010 — Legacy Mode

Historic runs imported from legacy systems may create simplified Run Capsules.

As additional information becomes available, these Capsules can be enriched over time.

Legacy status remains visible to preserve provenance.

---

# Business Principles

- The archive builds itself.
- Contributors should not duplicate effort.
- Historical authenticity is paramount.
- Capsules should become richer over time.
- Every run deserves preservation.

---

# Completion Criteria

This document is complete when:

- Automatic assembly is defined.
- Lifecycle states are documented.
- Historical locking is enforced.
- Incremental enrichment is supported.
- Legacy imports are accommodated.
